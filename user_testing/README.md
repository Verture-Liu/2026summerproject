# Pilot usability session

Materials for a prespecified pilot usability session of the PaleoRigor desktop
application, addressing the outstanding user-evaluation gap in the manuscript.

| File | Purpose |
| --- | --- |
| `PROTOCOL.md` | The frozen protocol. Read it before running anything. |
| `participant_brief.md` | Read aloud or handed to the participant. Contains no hints. |
| `observer_record.md` | The form filled in during the session. One per participant. |
| `fixtures/` | Synthetic test files given to the participant. |
| `make_fixtures.py` | Regenerates the fixtures from a fixed seed. |

## Order of operations

1. Read `PROTOCOL.md` in full.
2. Get written consent from the participant (email is fine).
3. Copy `fixtures/` to the participant's machine, or hand it over on a drive.
4. Run the session. Do not rehearse it first with the same person.
5. Fill in `observer_record.md` during the session, not from memory afterwards.

## What these data can and cannot support

**Can support:** a list of specific, observed barriers to installation, use and
interpretation, and the statement that the expert-gating behaviour was or was
not understood by a target-population user.

**Cannot support:** that the software is usable, learnable or trusted by
paleobiologists in general. One non-independent participant does not establish
that, and the manuscript must not imply it.

## Before these results go into the manuscript

- Confirm with the institutional ethics committee whether this session needs
  review or a documented exemption.
- Replace the manuscript's current Ethics approval statement, which says no
  participants were recruited.
- State in the text that the participant was known to the author and that the
  session was a pilot with n = 1.
