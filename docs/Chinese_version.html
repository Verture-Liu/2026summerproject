核心原则

上传数据→ 识别文件类型→ 原始 QC→ 清洗 / 筛选→ Data Quality Gate→ 应用分析→ 报告 / 导出

agent 不应该把原始数据直接送入下游应用分析。一个更严谨的流程应该先检查输入数据，完成原始质量控制，根据需要进行清洗或筛选，再通过清洗后质量门，最后进入多肽、古 DNA 或微生物组等应用分析。

关键规则：原始数据 → QC → 清洗/筛选 → 清洗后质量门 → 下游分析。
2

如何启动

步骤

  1. 在 VS Code 中打开项目文件夹：2026summerproject。
  2. 在 VS Code 的 Terminal 里输入下面的命令启动本地程序。
  3. 打开终端提示的本地网页。默认情况下，程序会自动打开浏览器。
  4. 上传数据文件，输入自然语言任务，点击生成 workflow。
  5. 检查 workflow，选择结果保存文件夹，勾选本地运行确认，再运行。

VS Code Terminal 启动命令

第一次使用时，如果还没有创建虚拟环境，输入：

cd /Users/tianaoliu/Documents/vscode/2026summerproject
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/research-agent

以后已经安装好环境后，只需要输入：

cd /Users/tianaoliu/Documents/vscode/2026summerproject
.venv/bin/research-agent

如果不想自动打开浏览器，或者想固定端口，可以输入：

cd /Users/tianaoliu/Documents/vscode/2026summerproject
.venv/bin/research-agent --no-browser --port 8000
如果页面能打开但 workflow 生成失败，优先检查 API key、模型配置和网络；如果 workflow 能生成但运行失败，优先检查本地工具是否安装。

基本使用流程

阶段用户看到什么agent 做什么
上传文件列表保存上传文件，并识别文件格式。
规划JSON workflow把用户请求转换为已注册的本地 skill 步骤。
审核待批准 workflow等待用户确认，不会自动执行本地任务。
运行步骤状态和输出列表逐步执行 skills，并保存日志、指标和输出结果。
导出HTML、CSV、JSON、ZIP、FASTQ 等结果把最终可交付文件复制到用户选择的结果文件夹。

推荐输入指令

请识别这个 CSV 是否有表头，并整理成 label 和 sequence 两列。
请处理 AMPLiT 的 Validation.csv，完成肽序列校验、长度统计、重复序列删除，并导出干净 CSV。
请对这个 FASTQ 做 FastQC 质量检查，并生成 MultiQC 汇总报告。
请对这对 FASTQ 先做质量检查，再做清洗后质量门检查，最后准备进入微生物组成分析。
请检查这些本地工具是否可用：fastqc、multiqc、seqkit、seqtk、bowtie2、samtools、kraken2。

环境与工具

agent 不会自动安装大型生信工具。它会先检查当前 PATH，如果找不到，会根据 config/tool_envs.json 尝试使用 conda run -n 环境名 工具名。如果仍然找不到，就会提示用户需要安装什么。

工具推荐环境用途
FastQCPATH 或 FastQC 环境FASTQ 原始质量检查
MultiQCmultiqc_env汇总 QC 报告
seqkitPATH 或 seqkit 环境FASTA/FASTQ 统计、筛选和去重
seqtkseqtk 环境FASTQ 抽样
Bowtie2bowtie2_env宿主去除或短 reads 比对
BWAbwa_env古 DNA 比对
Samtoolssamtools_envBAM/SAM 处理
Kraken2kraken2_env微生物分类
mapDamage / DamageProfilermapdamage_env古 DNA 损伤模式分析

conda activate multiqc_env

常见问题

问题可能原因处理方式
工具显示 missing工具不在 PATH，或 conda 环境没有配置。检查 conda env list 和 config/tool_envs.json。
workflow 生成失败API key、模型配置或网络问题。检查 API 配置，或者先用更简单的指令重试。
workflow 看起来跳过 QC用户输入的是很窄的单工具任务。如果目标是完整分析，请明确要求先 QC、再清洗后质量检查、最后下游分析。
Data Quality Gate 报 warning可能有空序列、重复序列、无效字符、FASTQ 格式问题或双端 reads 数量不一致。先查看 data_quality_gate_report.json，再决定是否继续。
