# 本地科研数据处理 Agent 设计

## 1. 项目目标

构建一个可下载、可安装、在使用者电脑上运行的单用户科研数据处理 Agent 套件。用户双击启动入口后，程序启动本地服务并自动打开浏览器中的本地网页。用户提供自然语言任务与待处理文件，系统调用用户配置的外部大模型 API 理解需求并生成结构化流程；本地程序校验流程后，调用套件内已注册的 Skills 处理数据，最终在用户电脑上输出结果文件、图表、日志与可复现报告。

首版服务于个人小论文工作，不追求覆盖完整生信平台。系统应保持轻量，并允许通过更新程序包增加 Skills。服务器版本属于未来可选扩展，不是首版运行所需条件。

## 2. 核心职责边界

系统必须严格遵守以下职责划分：

1. **外部模型 API**
   - 理解用户自然语言。
   - 根据文件摘要和可用 Skills 清单生成结构化流程。
   - 解释流程或根据用户要求重新规划。
   - 不直接读取本地原始文件内容，除非本地程序明确提供经过限制的摘要。
   - 不直接执行命令、修改文件或生成不可审计的代码。

2. **本地 Agent 程序**
   - 管理模型配置和 API 调用。
   - 向模型提供用户需求、文件元数据、允许使用的 Skills 和流程 Schema。
   - 校验模型返回的流程。
   - 请求用户确认流程。
   - 调度 Skills、追踪状态、处理错误并汇总结果。

3. **Skills**
   - 实际读取和处理用户数据。
   - 只接受声明过的输入类型和参数。
   - 生成声明过的输出文件及结构化运行结果。
   - 验证输入、输出和关键中间结果。
   - 记录工具版本、参数、耗时、日志和错误。

因此系统的唯一主链路是：

```text
自然语言 + 文件
    -> 本地文件预检与摘要
    -> 外部模型 API 生成流程 JSON
    -> 本地流程校验
    -> 用户确认
    -> 本地 Skills 顺序执行
    -> 每步结果验证
    -> 最终文件、图表与复现报告
```

## 3. 架构方案

采用模块化单体架构。网页、API 后端、Agent、执行器和 Skills 位于同一项目，但通过明确接口分离。

### 3.1 网页界面

- 网页仅绑定本机回环地址，不是线上网站。
- 用户通过套件启动程序自动打开网页，不需要手动启动服务器。
- 输入自然语言任务。
- 上传文件或选择本地文件。
- 配置兼容 OpenAI 协议的模型 API。
- 查看文件预检结果。
- 查看、修改并批准流程。
- 查看运行进度、日志和资源占用。
- 预览并下载结果。
- 浏览和复用历史任务。

### 3.2 文件管理器

- 识别支持的文件格式。
- 计算文件校验值并读取安全的元数据摘要。
- 为每次任务创建隔离工作目录。
- 保护原始输入，不允许 Skill 原地覆盖。
- 管理步骤之间的文件引用。

### 3.3 模型适配器

首版支持 OpenAI 兼容接口，并允许配置：

- `base_url`
- `api_key`
- `model`
- 超时时间
- 重试次数
- 可选请求头

适配器负责隐藏不同供应商的小差异。Agent 核心不依赖特定模型厂商。

### 3.4 Agent 规划器

规划器向模型发送：

- 用户自然语言请求。
- 输入文件的类型、大小、列名或序列摘要等有限元数据。
- 已注册 Skills 的名称、用途、输入输出与参数 Schema。
- 允许返回的工作流 JSON Schema。
- 安全与资源限制。

模型必须返回结构化 JSON，不得返回可执行 shell 命令或任意代码。

### 3.5 流程校验器

流程校验器在执行前检查：

- Skill 是否存在且已启用。
- 输入文件类型是否匹配。
- 上一步输出能否作为下一步输入。
- 参数是否满足 Schema。
- 输出路径是否位于任务目录。
- 是否出现循环、缺失依赖或重复覆盖。
- 预计资源是否超过本机限制。
- 是否包含高风险或未授权动作。

流程校验通过后仍需用户批准，首版不支持静默自动执行。

### 3.6 Skills 执行器

- 按依赖顺序执行 Skill。
- 每个步骤在独立子目录运行。
- 捕获标准输出、错误输出、退出状态和耗时。
- 支持停止任务，但不破坏已完成结果。
- 失败后停止依赖该步骤的后续任务。
- 允许用户修正参数后从失败步骤重试。

### 3.7 结果与审计模块

输出结果包括：

- 最终处理文件。
- 中间结果索引。
- 图表。
- 经用户批准的 `workflow.json`。
- 每一步参数和软件版本。
- 输入与输出文件校验值。
- 模型规划响应的脱敏记录。
- HTML 运行报告。

## 4. Workflow JSON

工作流使用版本化 JSON 表示。核心字段如下：

```json
{
  "schema_version": "1.0",
  "task_summary": "从古代宏基因组数据中筛选候选抗菌肽",
  "steps": [
    {
      "id": "step_01",
      "skill": "fastq_quality_filter",
      "inputs": [{"source": "uploaded", "ref": "sample_1_r1"}],
      "parameters": {"min_length": 30},
      "outputs": [{"name": "filtered_reads", "format": "fastq.gz"}],
      "reason": "移除低质量和过短序列"
    }
  ]
}
```

模型只能引用 Skill 注册表中存在的名称。执行器不接受工作流中的命令字符串。

## 5. Skill 标准

每个 Skill 是一个可独立测试和调用的功能单元，至少包含：

```text
skills/<skill-name>/
  SKILL.md
  skill.yaml
  schemas/
    input.schema.json
    parameters.schema.json
    output.schema.json
  src/
  tests/
  examples/
```

其中：

- `SKILL.md` 面向模型和开发者描述用途、边界及示例。
- `skill.yaml` 提供机器可读注册信息。
- Schema 用于流程生成和执行前校验。
- `src/` 包含确定性执行逻辑或对外部工具的安全封装。
- `tests/` 包含正常输入、边界输入和失败场景。
- `examples/` 提供小型可运行样例，不包含大型数据库。

统一执行结果包括状态、输出文件、指标、警告、错误和运行环境信息。

## 6. 首批 Skills

### 6.1 通用文件与表格

1. 文件格式识别与完整性检查。
2. CSV、TSV、Excel 读取与导出。
3. 表格筛选、排序、合并、去重和缺失值处理。
4. 统计汇总与基础科研绘图。
5. 文件与结果比较。

### 6.2 生物信息数据

1. FASTA/FASTQ 基础校验和摘要。
2. FASTQ 质量评估与过滤。
3. 环境污染序列去除。
4. 人类宿主 DNA 去除。
5. 宏基因组组装。
6. ORF 提取及蛋白序列转换。
7. AMP 模型预测适配器。
8. 肽序列长度过滤。
9. 跨样本覆盖度过滤。
10. 肽序列去冗余。
11. 细胞毒性预测适配器。
12. 复现结果评分。

外部工具未安装或数据库缺失时，Skill 必须返回明确的依赖错误和安装指导，不能伪造结果。

## 7. 首个验证基准

首个端到端验证基于论文《Identification of antimicrobial peptides from ancient gut microbiomes》的纯计算流程，不包括肽合成、细胞实验或动物实验。

预置参考流程：

```text
FASTQ
  -> 环境污染序列去除
  -> 人类宿主 DNA 去除
  -> 小于 30 bp 的序列过滤
  -> 宏基因组组装
  -> ORF 提取和氨基酸转换
  -> AMP 预测
  -> ORF 长度过滤
  -> 至少五个样本出现的覆盖度过滤
  -> 去冗余
  -> 细胞毒性预测
  -> 候选肽结果
```

验证分为三层：

1. **Skill 单元验证**：使用小型固定数据检查每个 Skill。
2. **固定流程验证**：使用人工锁定的论文流程验证执行器。
3. **Agent 规划验证**：只提供自然语言要求、文件摘要和 Skills，让模型生成流程，再与参考流程比较。

主要评价指标：

- 流程步骤覆盖率和顺序正确性。
- Skill 与输入输出匹配率。
- 参数与论文方法的一致性。
- 各步骤记录数和候选数差异。
- 最终候选集合的重叠率。
- 重复运行的一致性。
- 失败定位与恢复能力。
- 报告和环境记录完整性。

论文报告的中间数字可作为参考检查点，但因软件版本、数据库和原始数据处理差异，应同时记录容许偏差和原因，不能把单一数字完全一致作为唯一成功标准。

## 8. 支持格式与资源策略

首版优先支持：

- CSV、TSV、XLSX
- TXT、JSON
- FASTA、FASTQ、FASTQ.GZ
- SAM、BAM、VCF、GFF 的识别与基础验证
- Newick

Skills 本身保持轻量。大型参考数据库、原始测序数据和外部软件不打包进入程序：

- 数据库按需安装和配置。
- 下载后缓存在用户指定目录。
- 每个 Skill 声明资源需求。
- 超过本机限制的流程在执行前提示。
- 为未来远程执行器保留接口。

## 9. 本机任务目录

每次任务使用独立目录：

```text
workspace/tasks/<task-id>/
  inputs/
  steps/
    step_01/
    step_02/
  outputs/
  figures/
  logs/
  workflow.draft.json
  workflow.json
  manifest.json
  report.html
```

原始文件默认只读。若文件较大，可记录外部绝对路径与校验值，而不是复制整个文件。

## 10. 错误处理

- API 请求失败：按配置重试并保留可读错误。
- 模型返回非法 JSON：自动请求一次格式修复，仍失败则要求重新规划。
- 流程不合法：指出具体步骤和原因，不执行。
- 文件格式错误：在调用模型前终止并说明问题。
- Skill 依赖缺失：给出缺失工具、版本和安装说明。
- Skill 执行失败：保存日志，停止依赖步骤，允许从失败点重试。
- 输出校验失败：将步骤标为失败，不把文件作为后续合法输入。
- 用户停止：安全结束当前进程并保留已经完成的产物。

API Key 必须脱敏，不写入工作流、日志或报告。

## 11. 测试策略

- Workflow JSON Schema 测试。
- 模型适配器模拟响应测试。
- 流程校验器的合法与非法流程测试。
- 每个 Skill 的单元和小型集成测试。
- 文件隔离与路径安全测试。
- 任务停止和失败恢复测试。
- AMP 参考流程的固定小数据端到端测试。
- 模型生成流程与金标准流程的自动评分测试。
- 同一输入重复执行的一致性测试。

测试默认使用小型数据夹具，不依赖下载完整论文数据集。

## 12. 首版明确不做

- 多用户账号与权限。
- 公网部署。
- 计费和配额。
- 任意代码执行。
- 模型自动创建并立即运行新 Skill。
- 将大型参考数据库打包进安装程序。
- 湿实验自动化。
- 无用户确认的全自动执行。

## 13. 可选的未来服务器迁移

保持以下接口稳定：

- 网页与后端 API。
- Workflow JSON。
- Skill 注册与执行协议。
- 文件存储抽象。
- 任务状态模型。

迁移服务器时，可分别替换本地文件存储、进程执行器和任务队列，而无需重写 Agent 规划逻辑和 Skills。

## 14. 本地交付与分发形态

产品的默认交付物是完整的本地 Agent 套件，而不是托管网站。内部保持“本地网页 + 本地后端 + Skills”的架构，同时提供一键启动入口：

- 开发阶段提供源码启动脚本。
- 启动后自动打开默认浏览器访问本地网页。
- 用户在首次运行时填写自己的 `base_url`、`api_key` 和 `model`。
- API 配置仅保存在本机；API Key 不进入任务产物。
- Windows 封装为 `.exe` 或安装包。
- macOS 封装为 `.app`。
- 安装包尽可能携带 Python 运行环境和轻量依赖，普通用户无需提前安装 Python。
- 大型数据库和重型生信软件由依赖检查助手按需引导安装，不强制塞入基础安装包。
- 打包层只负责启动本地服务和打开网页，不改变 Agent、Workflow JSON 或 Skill 协议。

建议的分发目录为：

```text
ResearchAgent/
  ResearchAgent.exe 或 ResearchAgent.app
  skills/
  runtime/
  examples/
  config/
  workspace/
```

## 15. 本地隐私边界

- 原始数据和 Skills 执行结果默认不离开用户电脑。
- 只有用户自然语言、Skill 清单和经过限制的文件摘要会发送至用户配置的模型 API。
- 文件摘要的内容必须在发送前展示或可检查。
- 用户可关闭部分文件摘要字段。
- 系统不得把完整 FASTQ、FASTA、表格或其他原始文件隐式发送给模型。
- 本地网页默认只监听 `127.0.0.1`，不暴露到局域网或公网。

## 16. 用户指定最终 FASTA 输出目录

用户必须在网页中点击“选择结果文件夹”，由本地后端打开操作系统原生目录选择窗口。系统不设置默认输出目录，也不接受网页直接提交任意文件系统路径。

规则如下：

- 未选择输出目录时，网页和后端都禁止执行任务。
- 所选目录与任务 ID 绑定，只保存在本机任务状态中。
- 任务内部目录继续保留完整工作流、日志和中间结果。
- 任务成功后，将最终步骤产生的 `.fasta`、`.fa`、`.faa` 或 `.fna` 文件复制到用户选择目录的根部。
- 将 `report.html`、`manifest.json` 和 `logs/` 复制到用户选择目录下的 `ResearchAgent记录/` 子目录。
- 不复制中间处理文件或中间 FASTA。
- 若最终步骤没有 FASTA 输出，则任务执行结果中明确提示“没有可导出的最终 FASTA”，不复制其他文件。
- 若目标目录已有同名文件，输出文件名自动追加任务 ID 的前 8 位，禁止覆盖已有文件。
- 复制后的最终文件路径和校验值记录在导出的 manifest 中。
