01 / THE PROBLEM

Rigour can be lost before the first biological result appears.

Ancient microbial evidence is scarce, fragmented and contamination-sensitive. A polished report cannot compensate for the wrong source file, an incompatible operation or an undocumented transformation.

01

Ambiguous requests

Research questions may omit the exact input, expected output or analytical boundary.

02

Source mismatch

A valid FASTQ file may still belong to the wrong accession, mate or download.

03

Invisible steps

Unrecorded filtering and conversion weaken provenance even when execution succeeds.

04

Over-interpretation

File identity and routine quality control do not establish ancient authenticity or biological validity.

03 / CAPABILITIES

Built around practical early-stage analyses.

Skills are predefined, inspectable wrappers. External bioinformatics tools run from configured local environments and missing dependencies are reported rather than installed silently.

TAB

Biological table curation

Header detection, column normalization, filtering, validation, deduplication, statistics, charts and export.

  • CSV and peptide tables
  • Traceable row-level changes
SEQ

Sequencing quality control

FASTQ detection, organization checks, FastQC, MultiQC and SeqKit summaries for raw sequencing evidence.

  • Single- and paired-end reads
  • Separated reports and metadata
SRC

Source-record verification

Compare local read counts, compressed sizes, accessions and mate organization with public repository records.

  • ENA and SRA metadata
  • File-level correspondence only
DNA

Ancient-DNA-ready workflows

Prepare bounded calls to adapter processing, host removal, alignment and damage-aware tools when references and environments are declared.

  • Explicit environment checks
  • Expert authentication remains required
META

Metagenome tool wrappers

Preprocessing, taxonomy, assembly, binning and functional-analysis entry points for installed local software.

  • Workflow compatibility checks
  • No automatic package installation
REC

Reproducibility records

Requested final outputs remain separate from intermediate files, run events, parameters and manifests.

  • Checksums and run reports
  • Reviewable evidence chain

INTERPRETATION STRESS TEST

Technically reproducible does not mean biologically valid.

For a retraction-associated record, PaleoRigor reproduced source-level properties while preserving an explicit boundary: clean files and matching metadata did not validate the retracted biological interpretation.

05 / HUMAN OVERSIGHT

Expert intervention is part of the method.

PaleoRigor is designed to expose decisions at the points where an error can still be corrected—not to replace domain judgement.

  1. Before planning

    Is this the right scientific question and source material?

    The researcher checks archaeological context, accession provenance and whether the requested analysis is meaningful.

  2. Before execution

    Is the proposed workflow compatible and sufficiently bounded?

    The researcher reviews inputs, references, parameters, expected outputs and the reason for each operation.

  3. After execution

    What conclusion can the retained evidence actually support?

    The researcher distinguishes file-level evidence and quality descriptors from authentication and biological interpretation.
